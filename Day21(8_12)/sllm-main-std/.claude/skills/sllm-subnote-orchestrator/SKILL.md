# sLLM 서브노트 오케스트레이터

## 산출물

```
report/서브노트_1일차_4반_박영서.docx
report/서브노트_2일차_4반_박영서.docx
```

2일차 노트에는 실습 가이드 2절이 요구한 다섯 항목이 전부 들어간다. 이해관계자
가치(Pain Point), AI 솔루션, 아키텍처 구성도, Base Model vs SFT Model, 평가 화면 스냅샷.

## 실행 모드

**하이브리드.** Phase 마다 성격이 다르다.

| Phase | 모드 | 이유 |
|---|---|---|
| 1. 실습 실행 | 단독 | 긴 배치 작업. 조율할 상대가 없다 |
| 2. 근거 수집 | 단독 (Phase 1과 **겹쳐서** 돈다) | 조사는 한 사람이 일관된 기준으로 해야 출처가 섞이지 않는다 |
| 3. 그림 + 집필 | **에이전트 팀** | 그림과 본문이 서로를 참조한다. 그림 목록이 절 구성을 바꾸고, 절 구성이 그림 배치를 바꾼다 |
| 4. 검수 | 단독 | 검수자는 집필 과정을 모르는 편이 낫다. 팀 대화에 섞이면 이미 합의된 것을 지적하지 못한다 |
| 5. 조립 | 단독 | 기계적 작업 |

모든 에이전트 호출에 `model: "opus"` 를 명시한다.

## Phase 0: 컨텍스트 확인

시작할 때 `_workspace/` 와 `outputs/` 를 보고 실행 모드를 정한다.

| 상태 | 요청 | 실행 |
|---|---|---|
| `_workspace/` 없음 | 무엇이든 | **초기 실행** — Phase 1부터 |
| 있음 | "이 절만", "그림만", "docx만" | **부분 재실행** — 해당 Phase만 |
| 있음 | "더 사람같이", "분량 늘려" | Phase 3(집필)~5 |
| 있음, `outputs/` 있음 | "학습 다시" | Phase 1부터. 이전 `outputs/` 는 보존 |
| 있음 | 소재가 바뀜 | `_workspace_prev/` 로 옮기고 **새 실행** |

부분 재실행일 때 앞 단계를 다시 돌리지 마라. 학습은 몇 시간이 걸리고, 결과가 바뀌지
않는데 다시 도는 것은 순수한 낭비다. 특히 **문체 지적 하나 때문에 재학습하는 일이
없어야 한다.**

## Phase 1 + 2: 실습 실행과 근거 수집 (겹쳐서 돈다)

여기가 이 하네스에서 시간을 가장 많이 아끼는 자리다. 순차로 돌리면 안 된다.

```
sft-runner 를 model: "opus" 로 호출
  └ venv 구성 → 학습을 run_in_background 로 띄움 → 즉시 반환

학습이 도는 동안 (수십 분 ~ 몇 시간)
  └ evidence-miner 를 model: "opus" 로 호출
      └ 01_evidence.md 의 A~E 를 채움
         A 과제 요구사항  B 실습 환경  C 데이터셋
         D 1일차 노트북   E 학습 설정과 구조

학습 완료
  └ sft-runner 가 평가 실행 → 스냅샷 → 00_run.md
  └ evidence-miner 가 F~H 를 채움
         F 학습 실행 결과  G 평가 결과  H 트러블슈팅
```

학습을 띄운 직후 사용자에게 예상 소요와 함께 진행 상황을 알린다. 몇 시간짜리 작업을
말없이 돌리지 마라.

- 출력: `outputs/*.json`, `models/hr-qwen-lora/`, `_workspace/logs/*.log`,
  `_workspace/snapshots/*.png`, `_workspace/00_run.md`, `_workspace/01_evidence.md`
- 완료 조건: 어댑터 2종 + outputs 4종 + 스냅샷 1장 이상, 근거 A~H 8개 절이 모두 채워짐

집필을 이 단계와 겹치지 마라. 근거가 절반만 모인 상태에서 쓰기 시작하면 나머지
절반을 기억으로 채우게 된다. 그림과 집필은 다르다 — 그건 Phase 3에서 같이 돈다.

### 학습을 건너뛰는 경우

사용자가 이미 돌려 둔 `outputs/` 가 있고 재학습을 원하지 않으면 Phase 1의 학습·평가를
건너뛰고 스냅샷만 굽는다. 이때 `_workspace/00_run.md` 에 **결과를 직접 만들지 않았다는
사실**을 적는다. 트러블슈팅 절에 없는 경험을 쓰지 않기 위해서다.

## Phase 3: 그림 + 집필 (에이전트 팀)

팀: **sketch-artist** + **subnote-writer** (2명). 리더는 오케스트레이터.

```
TeamCreate(team_name="subnote-team", members=[sketch-artist, subnote-writer])
TaskCreate:
  T1 subnote-writer : 두 노트의 절 구성과 필요한 그림 목록 확정 → sketch-artist 에게 전달
  T2 sketch-artist  : 그림 제작 + 자체 검수 (T1 의존)
  T3 subnote-writer : 본문 집필 (T2와 병행. 그림 완성분부터 배치)
  T4 양쪽           : 배치 순서 합의 — 그림이 본문보다 먼저 온다
```

이 둘을 따로 돌리면 안 되는 이유: subnote-writer 가 "여기 그림이 필요하다"를 발견하는
시점은 본문을 쓰는 중이고, sketch-artist 가 "이 개념은 한 장에 안 들어간다"를 발견하는
시점은 그리는 중이다. 두 발견이 서로의 계획을 바꾼다. 순차로 돌리면 한쪽이 반드시
상대의 이미 끝난 결과에 맞춰 타협하게 된다.

2일차 3번 항목(아키텍처 구성도)이 이 Phase 의 무게중심이다. 가이드는 이 그림이
데이터셋 흐름, LoRA Adapter 학습 과정, Base 와 Adapter 가 결합되어 최종 서비스에
적용되는 구조까지 한눈에 보이도록 요구한다.

- 출력: `_workspace/diagrams/*.{js,png}`, `_workspace/02_diagrams.md`,
  `_workspace/03_manuscript_day1.md`, `_workspace/03_manuscript_day2.md`
- 완료 조건: 두 원고의 모든 `![](...)` 가 실제 파일을 가리키고, 모든 PNG 가 원고에서 쓰임

## Phase 4: 검수 (단독)

**human-voice-qa** 를 `model: "opus"` 로 호출한다. 출력 `_workspace/04_qa.md`.

검수자가 제일 먼저 도는 것은 하드 게이트다. 정의는
`subnote-writing/scripts/voice-gate.sh` 한 곳에 있고, 집필자와 검수자가 같은 스크립트를
돌린다. 문체 11개와 구조 3개를 센다. 사용자가 직접 반려한 항목과 가이드가 요구한
구조라 문체 취향이 아니라 통과 조건이다.

게이트를 늘릴 때 에이전트 정의 파일에 grep 을 새로 적지 마라. 스크립트를 고치고
`.md` 에는 항목 이름만 적는다. Day19 에서 양쪽에 복제돼 있다가 한쪽만 고쳐진 적이 있다.

- 두 원고를 **따로 판정**한다. 1일차가 통과했는데 2일차 때문에 둘 다 반려하면
  집필자가 통과한 원고를 다시 손대게 된다
- CRITICAL 0건 → Phase 5
- CRITICAL 있음 → subnote-writer 에게 지적 목록을 넘겨 수정 후 재검수. **최대 2회.**
  3회째에도 남으면 남은 항목을 사용자에게 그대로 보고하고 판단을 맡긴다.
  같은 항목을 무한히 돌리는 것이 가장 나쁜 결말이다

## Phase 5: 조립 (단독)

**doc-builder** 를 `model: "opus"` 로 호출한다.

- 출력: `report/` 아래 `.docx` 2개
- 완료 조건: 문서별 이미지 개수 == 해당 원고의 `![](...)` 개수, 2일차 문서에 스냅샷
  포함, 문단·표 수가 0이 아님

## 데이터 전달

파일 기반(산출물) + 태스크 기반(Phase 3 조율).

```
_workspace/
├── 00_run.md                  실행 기록 — 설정, 소요 시간, 겪은 문제
├── 01_evidence.md             근거 A~H — 모든 사실의 단일 출처
├── 02_diagrams.md             그림 목록 · 배치
├── 03_manuscript_day1.md      1일차 원고
├── 03_manuscript_day2.md      2일차 원고
├── 04_qa.md                   검수 결과
├── diagrams/                  NN_이름.js (재생성용) + NN_이름.png
├── snapshots/                 실행 화면 캡처 (원본)
└── logs/                      train.log · eval.log (stdout 원본)
```

`_workspace/` 는 지우지 않는다. 부분 재실행과 사후 검증이 전부 여기에 의존한다.
특히 `.js` scene 파일과 `logs/` — 이게 없으면 그림 하나를 고치거나 스냅샷을 다시
굽으려고 학습부터 다시 돌려야 한다.

## 에러 핸들링

| 상황 | 처리 |
|---|---|
| 학습이 시작 직후 죽음 | 로그 끝 40줄로 원인 분류 후 보고. 원인 모른 채 재시도하지 않는다 |
| MPS OOM | `SFT_MAX_LENGTH=256`, `SFT_GRAD_ACCUM=16`. 바꾼 값을 `00_run.md` 에 기록 |
| 학습이 너무 오래 걸림 | 죽이지 말고 경과와 남은 스텝을 보고한 뒤 판단을 받는다 |
| 데모 사이트 미도달 | 재시도하지 않는다. `term_shot.py` 로 실행 화면을 굽는다 |
| 노트북 출력 셀이 비어 있음 | `(실행 결과 없음)` 으로 적고 사용자에게 확인. 수치를 추정하지 않는다 |
| Chrome 이 매달림 | `--headless=old` 확인. `=new` 는 이 환경에서 멈춘다 |
| 한글이 손글씨로 안 나옴 | 폰트 base64 임베딩 실패. 그림 전체를 다시 굽는다 |
| 근거끼리 상충 | 지우지 말고 둘 다 적는다. 불일치 자체가 트러블슈팅 소재다 |
| QA CRITICAL 반복 | 2회까지만 자동 수정. 이후 사용자에게 넘긴다 |
| 이미지 누락 | 조립은 완료하되 누락 목록을 **반드시** 보고 |
| SFT 가 Base 에 짐 | 결과를 고치지 않는다. 왜 그랬는지가 서브노트에서 가장 값나가는 대목이다 |

## 테스트 시나리오

**정상 흐름** — "가이드대로 서브노트 만들어줘"
→ Phase 1 학습을 백그라운드로 띄우고 사용자에게 예상 소요 보고 → 그 동안 근거 A~E
→ 학습 완료 후 평가, 스냅샷, 근거 F~H → Phase 3 팀으로 그림 4장 + 원고 2개
→ Phase 4 CRITICAL 0 → Phase 5 docx 2개, 2일차 이미지에 스냅샷 포함 확인
→ 사용자에게 파일 경로와 피드백 요청

**에러 흐름** — 학습 중 MPS OOM 으로 죽음
→ 로그 끝 40줄에서 OOM 확인 → `SFT_MAX_LENGTH=256`, `SFT_GRAD_ACCUM=16` 으로 재시도하며
사용자에게 알림 → `00_run.md` 에 바꾼 값과 이유 기록 → 이후 정상 흐름. 근거 E절에
코드 기본값과 실제 실행값을 둘 다 적고, 트러블슈팅 절의 사례가 된다

**부분 재실행 흐름** — "2일차 4번 절 숫자가 너무 많아"
→ Phase 0에서 부분 재실행 판정 → subnote-writer 만 호출, 2일차 원고의 해당 절만 수정
→ Phase 4 재검수 → Phase 5에서 2일차 문서만 다시 조립 (Phase 1·2·3 건너뜀)

## 완료 후

사용자에게 피드백을 요청한다 — 결과물 품질, 팀 구성, 워크플로우 순서.
피드백이 오면 해당 대상을 직접 고치고 CLAUDE.md 변경 이력에 기록한다.

| 피드백 | 고칠 곳 |
|---|---|
| 특정 표현이 어색하다 | `voice-guide.md` 0절 금지표에 **지적받은 문장 그대로** + 고친 문장을 추가하고, 기계로 셀 수 있으면 `voice-gate.sh` 에도 넣는다 |
| 글이 기계 같다 (범위가 넓음) | `subnote-writing/references/voice-guide.md` |
| 노트 구성이 아쉽다 | `subnote-writing/SKILL.md` 의 골격 |
| 그림이 깔끔하다 | `handdrawn-diagram/SKILL.md` 배치 원칙 |
| 사실이 틀렸다 | `sllm-evidence-mining` 수집 순서 |
| 학습 설정을 바꾸고 싶다 | `sft-practice-run/SKILL.md` 2절 |
| 순서가 이상하다 | 이 파일의 Phase 구성 |

문체 지적을 받으면 일반화해서 적지 마라. `AI 같은 표현을 피한다` 는 다음 실행에서
아무것도 막지 못한다. 반려된 문장을 그대로 왼쪽에 박아 두는 것이 유일하게 작동하는
형태다. 셀 수 있는 것은 반드시 게이트 스크립트로 내려서 검수자가 판단하지 않게 만든다.
