# sllm-main-std — SKALA sLLM Fine-Tuning 개인과제

## 하네스: sLLM SFT 서브노트

**목표:** Qwen2.5-1.5B 에 LoRA SFT 를 실제로 돌려 나온 결과를 근거로, 손으로 그린 듯한
다이어그램과 사람이 쓴 듯한 서술로 1일차/2일차 서브노트를 제출용 .docx 까지 뽑아낸다.

**트리거:** 과제·서브노트 관련 요청(작성, 수정, 재실행, 학습 재실행, 그림 교체,
분량 조정, docx 재조립)이 오면 `sllm-subnote-orchestrator` 스킬을 사용하라.
학습만 돌리는 요청은 `sft-practice-run`, 원고 문장만 다루는 요청은 `subnote-writing`
이 직접 받는다. "LoRA가 뭐야" 수준의 단순 질문은 직접 응답해도 된다.

**소재 고정값**
- 제출자: **4반 박영서** — 두 노트의 표지 줄에 그대로 넣는다. `○반 ○○○` 자리표시자 금지
- 실습 가이드: `../sLLM_FineTuing_실습가이드.pdf` — **한 단계 위다.** 2절이 서브노트
  필수 항목, 11절이 평가 지표 정의, 13절이 이해의 깊이 상한
- 산출물: `report/서브노트_1일차_4반_박영서.docx`, `report/서브노트_2일차_4반_박영서.docx`
- 수업 권장 학습 설정: `SFT_MAX_LENGTH=384 SFT_EPOCHS=2 SFT_LEARNING_RATE=1e-4`.
  코드 기본값(512 / 3 epoch)과 다르므로 근거에 둘 다 적는다
- 데모 사이트 `http://172.16.21.96:5173/` 는 교수 담당 내부망이라 대개 닿지 않는다.
  가이드가 허용한 `evaluate_model.py` 실행 화면 캡처가 기본 경로다

**2일차 노트 필수 5항목** (가이드 2절. 순서와 키워드를 바꾸지 않는다)

이해관계자 가치(Pain Point), 이를 해결하기 위한 AI 솔루션, 아키텍처 구성도,
Base Model vs SFT Model, 평가 화면 스냅샷. 5번은 캡처 첨부가 본체라 글로만 적으면
미제출이고, 손그림으로 대체하면 증빙이 아니다.

**원고 하드 게이트** (사용자가 직접 반려한 항목. 하나라도 남으면 다시 쓴다)

큰따옴표 0(코드 블록 예외), 중간점 0, 이모지 0, 물음표 0(위치 무관), 의문형 제목 0,
그림 뒤 캡션 0, 글이 자기를 설명하는 문장 0, 이름 자리표시자 0, `>` 인용 블록 0개,
인용 앞 도입 한 줄 문단 0, 예고형 도입 문장 0. 여기에 구조 검사 3종(제출자 줄,
2일차 필수 5항목, 2일차 스냅샷 이미지)이 붙는다.

지적받은 실제 문장과 고친 문장은 `subnote-writing/references/voice-guide.md` 0절에
있고, 게이트 정의는 `subnote-writing/scripts/voice-gate.sh` **한 곳뿐이다** — 집필자와
검수자가 같은 스크립트를 돌린다. 게이트를 늘릴 때 에이전트 `.md` 에 grep 을 새로 적지 마라.

**절 하나에 측정 수치 10개 이하** (본문 기준, 표 안은 제외). 이 실습은 숫자가 특히
많아서 근거를 다 옮기면 논문으로 읽힌다. 사용자가 내용이 심오하다고 반려한 자리다.
