# 실습과제 풀이 정리

`실습과제.md`의 과제 ①~④를 구현하면서 무엇을 왜 그렇게 했는지 정리한 문서입니다.
과제 자체의 설명은 `실습과제.md`를, 여기서는 **작성한 코드와 그 이유**를 봅니다.

## 한눈에 보기

| 과제 | 주소 | 응답 | Service 메서드 | Controller 메서드 |
| --- | --- | --- | --- | --- |
| ① 날씨별 | `GET /api/menu/weather/{weather}` | 문자열 | `recommendByWeather` | `menuByWeather` |
| ② 기분별 | `GET /api/menu/mood/{mood}` | 문자열 | `recommendByMood` | `menuByMood` |
| ③ 가격대별 | `GET /api/menu/price/search?min=&max=` | 문자열 | `recommendByPrice` | `menuByPrice` |
| ④ 나만의 | `GET /api/menu/my/{companion}` | 문자열 | `recommendByCompanion` | `menuByCompanion` |

네 개 모두 **문자열**로 응답합니다. JSON 응답은 기존에 만들어져 있는
`/api/menu/json/{category}`(`menuJson` 메서드)가 예시로 남아 있습니다.

수정한 파일은 4개입니다.

- `MenuService.java` — 추천 규칙(비즈니스 로직)
- `MenuController.java` — 주소와 메서드를 연결(웹 계층)
- `application.properties` — 에러 응답 설정 1줄
- `README.md` — API 목록 갱신

---

## 1. 역할 분리 — 왜 Service와 Controller를 나누나

이번에 추가한 코드는 예외 없이 **두 군데로 나뉘어** 들어갔습니다.

```
브라우저 ──HTTP──▶ MenuController ──자바 메서드 호출──▶ MenuService
                   (주소 해석 / 문장 조립)              (메뉴 고르는 규칙)
```

- `MenuService`는 **"어떤 메뉴를 고를까"** 만 안다. HTTP도, 주소도, JSON도 모른다.
- `MenuController`는 **"어떤 주소를 누가 처리할까"** 와 응답 모양만 안다. 메뉴 고르는 규칙은 모른다.

그래서 `recommendByWeather`는 `"칼국수"`라는 **메뉴 이름만** 돌려주고,
`"rainy 날씨에 어울리는 메뉴는 칼국수입니다."`라는 **문장은 Controller가** 만듭니다.

이렇게 나눠 두면 나중에 같은 추천 규칙을 화면용/앱용으로 다르게 보여줘야 할 때
`MenuService`는 손대지 않고 Controller만 바꾸면 됩니다.

## 2. 과제① — `switch` 표현식으로 규칙 쓰기

기존 `recommendByCategory`와 **똑같은 구조**입니다. 새로 배울 게 없는 게 정상입니다.

```java
public String recommendByWeather(String weather) {
    return switch (weather) {
        case "sunny" -> "비빔밥";
        case "rainy" -> "칼국수";
        case "hot"   -> "냉면";
        case "cold"  -> "김치찌개";
        default -> NOT_FOUND;
    };
}
```

`switch (…) { case A -> 값; }` 형태는 Java 14부터 쓸 수 있는 **switch 표현식**입니다.
`break`가 필요 없고, 전체가 하나의 값이 되므로 그대로 `return` 할 수 있습니다.

Controller 쪽은 문자열을 그대로 돌려줍니다. 반환 타입이 `String`이면
Spring이 그 문자열을 그대로 응답 본문으로 내보냅니다.

```java
@GetMapping("/menu/weather/{weather}")
public String menuByWeather(@PathVariable("weather") String weather) { … }
```

`@RequestMapping("/api")`가 클래스에 붙어 있어서, `@GetMapping`에는 `/api`를 **빼고** 적습니다.
최종 주소는 `/api` + `/menu/weather/{weather}` 입니다.

## 3. 과제② — 같은 구조를 값만 바꿔서 반복하기

①과 판박이입니다. 받는 값이 `weather` → `mood`로, 고르는 규칙이 날씨 → 기분으로 바뀔 뿐입니다.

```java
@GetMapping("/menu/mood/{mood}")
public String menuByMood(@PathVariable("mood") String mood) {
    String menu = menuService.recommendByMood(mood);

    if (MenuService.NOT_FOUND.equals(menu)) {
        return mood + "에 대한 " + menu + ". (happy, sad, tired, stressed 중에서 골라 주세요)";
    }
    return "기분이 " + mood + "일 땐 " + menu + " 어떠세요?";
}
```

같은 모양이 반복된다는 것 자체가 배울 점입니다. **주소를 하나 늘리려면
Service에 규칙 하나 + Controller에 매핑 하나** — 이 짝이 기본 단위입니다.

### 참고: JSON으로 응답하고 싶다면

반환 타입만 바꾸면 됩니다. 기존 `menuJson` 메서드가 그 예시입니다.

```java
@GetMapping("/menu/json/{category}")
public MenuResponse menuJson(@PathVariable("category") String category) {
    String menu = menuService.recommendByCategory(category);
    return new MenuResponse(category, menu, "오늘은 " + menu + " 어떠세요?");
}
```

`@RestController`가 붙어 있으면 **객체를 돌려주는 순간 Spring이 JSON으로 바꿔서** 내보냅니다.
따로 변환 코드를 쓰지 않습니다. 이 변환을 담당하는 게 Jackson 라이브러리이고,
`spring-boot-starter-web`에 이미 들어 있습니다.

`MenuResponse`는 `record`입니다. 필드 3개짜리 클래스를 한 줄로 정의한 것이고,
Jackson은 record의 필드 이름(`category`, `menu`, `message`)을 그대로 JSON 키로 씁니다.

즉 **문자열이냐 JSON이냐는 반환 타입 하나로 갈린다** — 이 점만 기억하면 됩니다.

## 4. 과제③ — `@PathVariable` 과 `@RequestParam` 의 차이

이번 과제에서 진짜 새로 배우는 부분입니다.

| | 주소 모양 | 애노테이션 |
| --- | --- | --- |
| 경로의 일부 | `/api/menu/mood/happy` | `@PathVariable` |
| `?` 뒤 질의 문자열 | `/api/menu/price/search?min=5000&max=10000` | `@RequestParam` |

```java
@GetMapping("/menu/price/search")
public String menuByPrice(@RequestParam("min") int min,
                          @RequestParam("max") int max) { … }
```

**타입이 `String`이 아니라 `int`** 인 점을 보세요. 주소로 들어오는 값은 원래 전부 문자열인데,
Spring이 `int`로 알아서 바꿔 줍니다. 숫자가 아닌 값(`?min=abc`)이 오면
변환에 실패해서 Spring이 자동으로 400을 돌려줍니다. `min` 자체를 빼먹어도 400입니다.

### 주소를 `/menu/price` 가 아니라 `/menu/price/search` 로 만든 이유

기존에 이런 매핑이 이미 있습니다.

```java
@GetMapping("/menu/{category}")   // /menu 뒤 "한 칸"을 전부 받아 감
```

`/menu/price`로 만들었다면 이 매핑과 모양이 같아져서 충돌합니다.
`/menu/price/search`는 `/menu` 뒤가 **두 칸**이라 `{category}`(한 칸)와 겹치지 않습니다.

이번에 추가한 4개 주소가 모두 두 칸(`weather/rainy`, `mood/happy`, `price/search`, `my/solo`)인 것도
같은 이유입니다. 첫 칸이 `weather`/`mood`/`price`/`my`로 서로 다르고 기존 `json`과도 달라서
서로 간에도 충돌하지 않습니다.

> 매핑이 충돌하면 앱이 **시작할 때** `Ambiguous mapping` 오류로 죽습니다.
> `./gradlew test`의 `contextLoads` 테스트가 이걸 잡아 줍니다.

### `min > max` 를 400으로 처리하기

`실습과제.md`가 "생각해 볼 점"으로 남겨 둔 부분입니다.

```java
if (min > max) {
    throw new ResponseStatusException(
            HttpStatus.BAD_REQUEST,
            "min(" + min + ")은 max(" + max + ")보다 클 수 없습니다.");
}
```

`min=20000&max=5000`은 **서버 잘못이 아니라 요청 잘못**입니다.
이럴 때 200 OK에 "잘못됐어요"라고 적어 보내면, 프로그램은 성공/실패를 구분할 수 없습니다.
HTTP 상태 코드로 알려 주는 것이 REST의 방식입니다.

- `2xx` 성공 / `4xx` 요청한 쪽 잘못 / `5xx` 서버 잘못

`ResponseStatusException`을 던지면 Spring이 그 상태 코드로 응답을 만들어 줍니다.

**다만 안내 문구는 기본적으로 응답에서 빠집니다.** `application.properties`에 한 줄이 필요합니다.

```properties
server.error.include-message=always
```

Spring Boot 2.3부터 이 설정의 기본값이 `never`입니다. 에러 메시지에 내부 정보가
새어 나가는 걸 막기 위한 안전 장치인데, 실습에서는 메시지를 봐야 하니 켰습니다.
(실제 서비스에서는 켤지 말지 신중하게 판단합니다.)

설정 전후 응답 차이:

```jsonc
// server.error.include-message=never (기본값)
{"timestamp":"…","status":400,"error":"Bad Request","path":"/api/menu/price/search"}

// server.error.include-message=always
{"timestamp":"…","status":400,"error":"Bad Request",
 "message":"min(20000)은 max(5000)보다 클 수 없습니다.","path":"/api/menu/price/search"}
```

## 5. 과제④ — 기존 코드 재사용

추천 기준은 **같이 먹는 사람**으로 정했습니다.

```java
public String recommendByCompanion(String companion) {
    return switch (companion) {
        case "solo"   -> "라면";
        case "friend" -> "피자";
        case "family" -> "불고기";
        default -> randomMenu();   // ← 여기만 다름
    };
}
```

앞의 셋과 달리 `default`에서 `NOT_FOUND`가 아니라 **이미 만들어져 있는 `randomMenu()`** 를 부릅니다.
`menus` 리스트를 다시 만들지 않고 기존 메서드를 그대로 쓴 것입니다
(`실습과제.md`가 "`menus` 리스트를 활용해도 좋다"고 안내한 부분).

같은 클래스 안의 메서드라서 `this.randomMenu()`처럼 그냥 부르면 됩니다.

## 6. 없는 값이 들어왔을 때 — `NOT_FOUND` 상수

처음 구현했을 때 이런 응답이 나왔습니다.

```text
없는날씨 날씨에 어울리는 메뉴는 추천 가능한 메뉴가 없습니다입니다.
```

`"…없습니다" + "입니다."`가 이어 붙어서 말이 안 됩니다.
문장을 조립하기 **전에** "메뉴를 찾았는지"를 확인해야 합니다.

그래서 `MenuService`에 상수를 하나 뒀습니다.

```java
public static final String NOT_FOUND = "추천 가능한 메뉴가 없습니다";
```

Controller에서는 이 상수로 비교합니다.

```java
if (MenuService.NOT_FOUND.equals(menu)) {
    return weather + "에 대한 " + menu + ". (sunny, rainy, hot, cold 중에서 골라 주세요)";
}
```

**왜 상수로 뺐나** — 같은 문자열을 Service와 Controller 두 곳에 각각 적어 두면,
나중에 문구를 고칠 때 한쪽만 고치는 실수가 납니다. 그러면 `if` 조건이 조용히 안 맞게 됩니다.
한 군데에만 정의하고 이름으로 부르면 이런 실수가 생기지 않습니다.

**왜 `menu.equals(…)`가 아니라 `MenuService.NOT_FOUND.equals(menu)` 인가** —
`menu`가 `null`이면 `menu.equals(…)`는 `NullPointerException`이 납니다.
확실히 `null`이 아닌 쪽을 앞에 두는 것이 안전한 습관입니다.

> 참고: 기존 `menuByCategory`(`/api/menu/없는값`)에는 아직 같은 문제가 남아 있습니다.
> 같은 방식으로 고쳐 보는 것을 연습으로 해 보세요.

## 7. 확인 방법

```bash
./gradlew test      # 매핑 충돌 / 컴파일 오류를 먼저 잡는다
./gradlew bootRun
```

8080이 이미 쓰이고 있으면 다른 포트로 띄울 수 있습니다.

```bash
./gradlew bootRun --args='--server.port=8081'
```

```bash
curl "localhost:8080/api/menu/weather/rainy"
curl "localhost:8080/api/menu/mood/happy"
curl "localhost:8080/api/menu/price/search?min=5000&max=10000"
curl -i "localhost:8080/api/menu/price/search?min=20000&max=5000"   # 400 확인
curl "localhost:8080/api/menu/my/solo"
```

브라우저는 `http://localhost:8080` — 주황색 버튼 4개가 이제 실제 결과를 보여줍니다.

> `index.html`의 스크립트는 응답이 200이 아니면 본문을 읽지 않고 `오류: HTTP 400`만 표시합니다.
> 그래서 ③의 400 응답 **본문**은 화면이 아니라 위 `curl -i`로 확인해야 합니다.
> 화면에서도 보고 싶다면 `index.html`의 `if (!response.ok) { throw … }` 부분을
> 본문을 읽어서 보여주도록 고쳐 보세요.

## 8. 이번에 새로 나온 것 정리

| 항목 | 한 줄 설명 |
| --- | --- |
| `@RequestParam` | `?key=value` 형태의 값을 받는다 |
| `@PathVariable` | 주소 경로 중 `{…}` 자리의 값을 받는다 |
| 타입 자동 변환 | `int min` 처럼 적으면 Spring이 문자열을 숫자로 바꿔 준다 |
| `ResponseStatusException` | 원하는 HTTP 상태 코드로 응답을 끝낸다 |
| `server.error.include-message` | 에러 응답 본문에 message를 넣을지 결정 (기본 `never`) |
| 매핑 충돌 | 경로 칸 수와 리터럴이 겹치면 앱이 시작할 때 죽는다 |
| `switch` 표현식 | `case A -> 값;` — `break` 없이 값을 만든다 |
| `static final` 상수 | 같은 문자열을 여러 곳에 적지 않게 한다 |
