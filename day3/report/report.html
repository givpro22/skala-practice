학사관리시스템 요구사항 (설계 방향)

기능 요구사항

  • 학과·교수·학생·과목·수강신청 5개 대상을 관리한다
  • 학과는 여러 교수·학생·과목을 보유한다 (학과 1 : N)
  • 과목은 하나의 학과에 개설되고, 한 명의 교수가 담당한다
  • 학생은 여러 과목을 수강하고, 과목도 여러 학생이 수강한다 (N : M → enroll 교차 테이블로 분해)
  • 같은 학생이 같은 과목을 중복 신청할 수 없다 → UNIQUE(student_id, course_id)
  • 성적은 학기 중 "미평가" 상태가 존재한다 → score NULL 허용 (COALESCE/CASE로 표시 처리)

데이터 무결성 요구사항 (설계 방향)

항목설계 반영
식별자모든 테이블 SERIAL 기반 대리키 PK (자동 증가)
참조 무결성소속·개설·담당·신청 관계를 전부 FK로 강제, 학생 삭제 시 수강이력은 ON DELETE CASCADE
도메인 제약직급(교수/부교수/조교수) · 학년(1~4) · 학적상태(재학/휴학/졸업) · 학점(1~3) · 정원(>0) · 성적(0~100)을 CHECK로 제한
중복 방지학과명, 교수·학생 이메일, (학생, 과목) 조합에 UNIQUE
기본값학적상태 '재학', 정원 30, 수강신청일 CURRENT_DATE

3. ERD 설계

까마귀발(Crow's Foot) 표기. 관계선은 서로 겹치지 않게 배치했고, 좌측 상단에 범례(설명문)를 포함했다.

4. CREATE TABLE — 제약조건 포함 DDL 작성

SQL — sql/02_ddl_tables.sql (제약조건 포함 전체 DDL)

CREATE SCHEMA IF NOT EXISTS academy; SET search_path TO academy; -- 1) 학과 CREATE TABLE department ( dept_id SERIAL PRIMARY KEY, dept_name VARCHAR(50) NOT NULL UNIQUE, office VARCHAR(50), established_date DATE NOT NULL ); -- 2) 교수 (department 1:N professor) CREATE TABLE professor ( prof_id SERIAL PRIMARY KEY, prof_name VARCHAR(30) NOT NULL, dept_id INT NOT NULL REFERENCES department(dept_id), position VARCHAR(20) NOT NULL CHECK (position IN ('교수', '부교수', '조교수')), email VARCHAR(100) NOT NULL UNIQUE, hire_date DATE NOT NULL ); -- 3) 학생 (department 1:N student) CREATE TABLE student ( student_id SERIAL PRIMARY KEY, student_name VARCHAR(30) NOT NULL, dept_id INT NOT NULL REFERENCES department(dept_id), grade INT NOT NULL CHECK (grade BETWEEN 1 AND 4), email VARCHAR(100) NOT NULL UNIQUE, phone VARCHAR(20), -- NULL 허용 → COALESCE 실습 birth_date DATE NOT NULL, admission_date DATE NOT NULL, status VARCHAR(10) NOT NULL DEFAULT '재학' CHECK (status IN ('재학', '휴학', '졸업')) ); -- 4) 과목 (department 1:N course, professor 1:N course) CREATE TABLE course ( course_id SERIAL PRIMARY KEY, course_name VARCHAR(60) NOT NULL, dept_id INT NOT NULL REFERENCES department(dept_id), prof_id INT NOT NULL REFERENCES professor(prof_id), credits INT NOT NULL CHECK (credits BETWEEN 1 AND 3), semester VARCHAR(10) NOT NULL, capacity INT NOT NULL DEFAULT 30 CHECK (capacity > 0) ); -- 5) 수강신청 (student N:M course 교차 테이블) CREATE TABLE enroll ( enroll_id SERIAL PRIMARY KEY, student_id INT NOT NULL REFERENCES student(student_id) ON DELETE CASCADE, course_id INT NOT NULL REFERENCES course(course_id), enroll_date DATE NOT NULL DEFAULT CURRENT_DATE, score NUMERIC(5,2) CHECK (score IS NULL OR score BETWEEN 0 AND 100), UNIQUE (student_id, course_id) -- 중복 수강신청 방지 );

실행 결과 ① psql — 테이블 5개 생성 확인(\dt)과 교차 테이블 enroll의 제약조건 상세(\d). PK·UNIQUE·CHECK·FK(ON DELETE CASCADE)가 모두 반영됨. 전체 DDL 실행 로그는 outputs/02_ddl_result.txt.

실행 결과 ② pgAdmin 4 Query Tool — pg_constraint 카탈로그를 조회해 5개 테이블의 제약조건 21개(PRIMARY KEY 5 · FOREIGN KEY 6 · UNIQUE 4 · CHECK 6)가 전부 생성됐음을 확인.

6. SELECT + WHERE + ORDER BY 기초 조회

재학 중인 2학년 이상 학생을 학년 내림차순 → 이름 오름차순으로 조회.

7. COALESCE / CASE WHEN / 날짜 함수 활용

7-1. COALESCE — 연락처 NULL을 '연락처 미등록'으로 표시

SQL

SELECT student_id, student_name, COALESCE(phone, '연락처 미등록') AS phone_display FROM student ORDER BY student_id;

실행 결과 ① psql — phone이 NULL인 4명(김하람·최시우·윤지호·서예준)이 '연락처 미등록'으로 치환되어 표시됨.

실행 결과 ② pgAdmin 4 Query Tool — 동일 쿼리 실행, 12행 중 NULL 4건이 '연락처 미등록'으로 표시됨 (Total rows: 12).

7-2. CASE WHEN — 성적을 A/B/C/F 등급으로 변환, NULL은 '미평가'

SQL

SELECT e.enroll_id, s.student_name, c.course_name, e.score, COALESCE( CASE WHEN e.score >= 90 THEN 'A' WHEN e.score >= 80 THEN 'B' WHEN e.score >= 70 THEN 'C' WHEN e.score IS NOT NULL THEN 'F' END, '미평가' ) AS grade_letter FROM enroll e JOIN student s ON s.student_id = e.student_id JOIN course c ON c.course_id = e.course_id ORDER BY e.enroll_id;

실행 결과 ① psql — CASE로 구간 등급(90↑A, 80↑B, 70↑C, 그 외 F)을 매기고, CASE가 NULL을 반환하는 미평가 4건은 COALESCE로 '미평가' 처리.

실행 결과 ② pgAdmin 4 Query Tool — 동일 쿼리 실행, [null] 값이 '미평가' 등급으로 변환된 15행 확인 (Total rows: 15).

7-3. 날짜 함수 — 나이(AGE) · 입학연도(EXTRACT) · 재학일수(날짜 연산)

SQL

SELECT student_name, birth_date, EXTRACT(YEAR FROM AGE(CURRENT_DATE, birth_date)) AS age, EXTRACT(YEAR FROM admission_date) AS admission_year, CURRENT_DATE - admission_date AS days_since_admission FROM student ORDER BY age DESC;

실행 결과 ① psql — AGE()로 만 나이, EXTRACT로 입학 연도, DATE 뺄셈으로 재학 일수 계산 (기준일 2026-07-22).

실행 결과 ② pgAdmin 4 Query Tool — 동일 쿼리 실행, 나이 내림차순 12행 확인 (Total rows: 12).

8. 수강신청 교차 테이블 JOIN 조회

8-1. 5개 테이블 JOIN — 학생·학과·과목·담당교수·신청일 통합 조회

SQL

SELECT s.student_name AS 학생, d.dept_name AS 소속학과, c.course_name AS 수강과목, c.credits AS 학점, p.prof_name AS 담당교수, e.enroll_date AS 신청일 FROM enroll e JOIN student s ON s.student_id = e.student_id JOIN course c ON c.course_id = e.course_id JOIN professor p ON p.prof_id = c.prof_id JOIN department d ON d.dept_id = s.dept_id ORDER BY s.student_name, c.course_name;

실행 결과 ① psql — 교차 테이블 enroll을 축으로 student·course·professor·department 5개 테이블을 연결. 수강신청 15건 전체가 학과·교수 정보와 함께 조회됨.

실행 결과 ② pgAdmin 4 Query Tool — 동일 쿼리 실행, 한글 별칭(학생·소속학과·수강과목·학점·담당교수·신청일) 컬럼으로 15행 확인 (Total rows: 15).

8-2. (심화) LEFT JOIN + GROUP BY + HAVING — 수강신청 내역이 없는 학생

SQL

SELECT s.student_id, s.student_name, s.status, COALESCE(COUNT(e.enroll_id), 0) AS enroll_count FROM student s LEFT JOIN enroll e ON e.student_id = s.student_id GROUP BY s.student_id, s.student_name, s.status HAVING COUNT(e.enroll_id) = 0 ORDER BY s.student_id;

실행 결과 ① psql — INNER JOIN이면 수강 내역이 없는 학생이 결과에서 사라지므로 LEFT JOIN을 사용. 집계 후 HAVING으로 0건인 학생만 남김 — 졸업생 윤지호 1명.

실행 결과 ② pgAdmin 4 Query Tool — 동일 쿼리 실행, 수강신청 0건인 학생 1행(윤지호·졸업) 확인 (Total rows: 1).
