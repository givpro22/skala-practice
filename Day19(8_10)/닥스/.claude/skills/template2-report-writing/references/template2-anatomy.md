본문 87문단, 그림 8장. 아래 내용은 그 파일에서 직접 뽑은 것이다.

## 베낄 것과 베끼면 안 되는 것

원본을 참고하되 내용을 옮기지 않는다. 경계는 이렇다.

| 가져오는 것 | 가져오지 않는 것 |
|---|---|
| 절 순서와 비중 | FastAPI, Swagger, pydantic 같은 소재 |
| 문장의 온도 (경어체 + 반말 메모) | 문장 자체 |
| 트러블슈팅 3단 형식 | 원본의 트러블슈팅 사례 (init.py, 가상환경, Mac 환경) |
| 길이 편차를 크게 두는 방식 | 소주제 개수 5개라는 숫자 |
| 그림을 본문보다 먼저 두는 배치 | 그림의 내용 |

원본 문장을 그대로 옮겨 쓰면 표절이고, 소재만 바꿔 문장 구조를 통째로 복사해도
읽는 사람은 알아본다. 참고할 것은 **왜 이 순서인가**지 무엇이 적혀 있는가가 아니다.

자리와 역할은 유지하고 어미만 바꾼다.

## Lesson Learned 소주제의 실제 형태

원본의 5개 소주제는 성격이 제각각이다. 형태를 통일하지 않은 것이 요점이다.

1. **RestAPI를 사용하는 이유는?** — 자문자답 + 화살표. 5줄로 짧게 끝남
2. **RestAPI와 FastAPI의 관계** — 그림 한 장만. 본문 없음
3. **FastAPI의 기본 구조 및 역할** — 하위 항목 2개(Routers / Swagger UI)로 다시 쪼갬.
   Swagger UI 항목이 이 문서에서 가장 길고, 프론트엔드 관점의 1인칭 감상이 길게 붙음.
   중간에 "FastAPI 팁! > 나중에 시도해보기" 라는 곁가지 메모가 하나 끼어 있음
4. **Schema** — 그림 2장 + "처음에는 ~라고 생각했지만 깨달았습니다" 구조
5. **Pytest** — 3문장. 가장 짧음

> 길이 편차가 크다는 점이 중요하다. 3번째 항목이 1쪽인데 5번째는 3문장이다.
> 각 소주제를 균등한 분량으로 채우면 즉시 기계가 쓴 티가 난다.

2번처럼 **그림만 있고 본문이 없는 소주제**를 하나쯤 두는 것도 원본의 방식이다.
모든 소주제에 설명을 붙여야 한다는 법이 없다.

## 그림에 캡션이 없다

이게 원본에서 제일 놓치기 쉬운 부분이다. 그림 8장 중 **아래에 설명 줄이 붙은 것이
하나도 없다.** 그림이 뭔지 알려야 할 때는 그림 **위**에 짧은 명사형 이름표를 둔다.

```
API 스키마 예시
[[그림]]

데이터 베이스 스키마 예시
[[그림]]
```

그림 밑에 `> 이 그림은 A가 B를 모른다는 것을 보여준다` 같은 줄을 다는 순간
발표 슬라이드가 되고, 손으로 쓴 노트라는 인상이 깨진다.

## 트러블슈팅 3단 형식 (고정)

이 부분만은 형식이 일정하다. 사례마다 정확히 세 줄.

```
{제목}
문제 상황 : {무엇이 안 됐는지}
원인 : {진짜 이유. 처음에 잘못 짚었던 것도 같이 적는다}
해결 방안 : {무엇을 해서 해결했는지}
```

제목이 짧은 명사다 — `init.py`, `가상환경`, `포트확인`, `Mac 환경`, `pytest`.
문장형 제목을 붙이지 않는다.

원본 `init.py` 사례가 좋은 본보기다. 원인 칸에 **틀린 추측을 먼저 적고** 그 다음에
진짜 원인을 적는다.

> "원인 : 디렉토리 문제인줄 알고, api 폴더로 이동하였으나, 여전히 문제 발생하였습니다.
> 알고보니 pytest에서 api.~~로 폴더를 임포트하여 사용 중이었습니다."

## 문장부호 실측

원고를 쓰기 전에 이 숫자를 기억해 둔다. 원본 87문단 기준이다.

| 부호 | 원본 | 이 보고서 |
|---|---|---|
| 큰따옴표 `"` | 0회 | 0회 |
| 홑따옴표 `‘ ’` | 1회 | 1회까지 |
| 중간점 `·` | 1회 | 0회 |
| 이모지 | 1개 (😢) | 0개 |
| 화살표 `→` `↔` | 여러 번 | 적극적으로 |
| 느낌표 | 여러 번 | 적극적으로 |

원본이 1회 쓴 것을 0회로 내리는 건 사용자 지시다. 원본이 많이 쓰는 화살표와
느낌표는 반대로 아껴 쓰지 않는다.

## 이미지 배치 규칙

원본은 그림을 **본문보다 먼저** 놓는다. 그림을 보고 나서 설명을 읽는 순서다.
설명 뒤에 그림을 붙이면 글의 삽화가 되어 노트 느낌이 사라진다.

Word 문서에서 그림 폭은 본문 폭(약 16cm)에 맞추되, 세로로 긴 그림은 12cm 이하로
줄여 한 쪽에 그림과 글이 함께 들어가게 한다.
