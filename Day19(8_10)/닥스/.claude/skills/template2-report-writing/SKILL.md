# 템플릿2 양식 보고서 쓰기

## 템플릿2가 다른 두 템플릿과 갈리는 지점

세 템플릿은 같은 과제의 세 가지 답안 형식이다. 무엇을 쓰느냐가 아니라 **어떤 목소리로**
쓰느냐가 다르다.

| | 템플릿1 | **템플릿2** | 템플릿3 |
|---|---|---|---|
| 뼈대 | 코드 블록별 분해 | **주제별 서술 + 깨달음** | 고객가치 기획서 |
| 목소리 | 분석 노트 | **1인칭 회고** | 제안서 |
| 코드 | 전면에 나옴 | **필요할 때만 인용** | 거의 없음 |
| 그림 | 단계 흐름도 | **손그림 플로우** | 구조 트리 |

템플릿2의 문서는 "내가 이걸 어떻게 이해하게 됐는지"의 기록이다. 정리된 지식을
나열하면 템플릿1이 되어 버린다. **막혔던 지점과 뚫린 순간**이 본문의 뼈대여야 한다.

## 문서 골격

원본 템플릿2를 그대로 따르면 이 순서다.

```
제목 (한 줄, 명사구)
제출자 한 줄           ← 4반 박영서
주제 한 줄             ← 평서형 명사구. 원본은 여기가 의문문이지만 어미만 바꾼다
[손그림 플로우 1]      ← 전체 그림. 본문보다 먼저 온다. 밑에 캡션을 달지 않는다
설명                  ← 왜 이 기술인가. 3~5문단
[환경 구성 얘기]

Lesson Learned         ← 본문의 절반 이상. 소주제 4~7개
  소주제
    ├ 손그림 or 캡처   ← 필요하면 그림 위에 명사형 이름표 한 줄
    ├ 서술 (2~5문단)
    └ 깨달은 것 한 줄

트러블 슈팅            ← 문제 상황 / 원인 / 해결 방안 3단 고정
  사례 4~6개           ← 제목은 짧은 명사 (카테고리 값 불일치, 8080의 401)

마지막 한 줄 메모       ← "+ 파일 저장 누르는 것 잊지 말기" 자리. 이모지 없이
```

소주제 하나쯤은 그림만 두고 본문을 안 써도 된다. 원본이 그렇게 한다.

## 먼저 확인할 것 — 이게 있으면 원고를 다시 쓴다

사용자가 직접 반려한 항목이다. 취향 조정이 아니라 통과 조건이다. 각 항목의
대체 문장은 `references/voice-guide.md` 0절에 실제 지적 사례와 함께 있다.

| 항목 | 허용 |
|---|---|
| 본문의 큰따옴표 `"` | 0회. 코드 블록 안의 Java 문법만 예외 |
| 중간점 `·` | 0회. 나열은 쉼표로 |
| 이모지 | 0개 |
| 물음표 | 0회. 위치를 가리지 않는다. 자문자답도 안 쓴다 |
| 그림 뒤 `>` 캡션 | 0회. 원본 템플릿2는 그림 8장에 캡션이 하나도 없다 |
| 글이 자기를 설명하는 문장 | 0회 |
| `>` 인용 블록 | 0개 |
| 인용 앞 도입 한 줄 문단 | 0회 |
| 예고형 도입 문장 | 0회 |

전부 기계로 셀 수 있으므로 눈으로 세지 말고 스크립트를 돌린다.

```bash
bash .claude/skills/template2-report-writing/scripts/voice-gate.sh _workspace/03_manuscript.md
```

마지막 셋이 사용자가 독백이 많다고 반려한 자리다. 인용 블록마다 앞에 도입 한 줄을
세우면 이런 리듬이 된다.

```
실습 가이드는 이 당황을 미리 예상하고 있었습니다.

> (인용)

교수님도 같은 선을 그으셨습니다.

> (인용)
```

말을 꺼내기 전에 누가 말했는지부터 알리는 줄이 반복되면서 혼잣말이 된다. 출처는
앞 문단의 **마지막 문장으로 붙이고**, 인용 블록은 축자로 옮길 수 있고 어투 자체가
정보인 것 하나만 남긴다. 요약해서 다시 쓴 문장을 인용 부호에 넣으면 어투가 본문과
어긋나서 그 대목만 지어낸 티가 난다 — 코드 주석 의역이 여기서 걸렸다.

`글이 자기를 설명하는 문장` 도 자주 새어 나온다. 이런 것들이다.

- `이 보고서는 그 열 개를 하나씩 다 이해한 기록이 아닙니다.` — 본문이 아니라 본문 해설
- `솔직하게 적어 둡니다.` — 할 말을 하기 전에 하겠다고 예고하는 군더더기
- `그 얘기부터 하겠습니다.` / `정리하자면` — 사람은 노트에 목차 안내를 달지 않는다
- `한 가지 더 배운 게 있습니다.` / `제가 이 절에서 정말 적고 싶은 건` — 지워도 뒤
  문장이 그대로 산다. 그러면 그 줄은 내용이 아니라 예고다

발견하면 대체 문장을 찾지 말고 **줄을 통째로 지운다.** 지우고 바로 본론으로 들어가면
문장이 오히려 좋아진다.

## 사람이 쓴 글로 읽히게 하는 법

위 표를 통과했다는 전제에서, 나머지 셋이 문체를 결정한다.

**1. 문단 길이를 고르게 만들지 마라.** AI 글의 가장 큰 냄새는 모든 문단이 3~4문장으로
균일하다는 것이다. 한 문장짜리 문단을 섞어라. 특히 깨달음을 적을 때.

**2. 결론을 매 절 끝에 붙이지 마라.** "이를 통해 ~을 배울 수 있었습니다"를 절마다
달면 사람이 아니라 템플릿이 쓴 글이 된다. 어떤 절은 그냥 사실을 적고 끝낸다.

**3. 헤매던 흔적을 남겨라.** "처음에는 A라고 생각했는데 알고 보니 B였다"는 구조가
있어야 한다. 처음부터 옳게 이해한 서술만 늘어놓으면 학습 기록이 아니라 요약본이다.

금지 어휘 — 나오면 즉시 다시 쓴다:

> 뿐만 아니라, 나아가, 이를 통해 ~할 수 있었습니다(반복), 중요한 것은 ~라는 점입니다,
> 단순히 ~이 아니라 ~입니다(반복), 결론적으로, 종합하면, ~에 대한 깊은 이해를 얻었습니다,
> 핵심은 ~이다(반복), 앞으로도 ~하겠습니다

반대로 화살표(→, ↔)와 느낌표, 물결표는 아끼지 않는다. 원본이 `바~로 그 표준화된
규칙(약속)!!!` 처럼 실제로 그렇게 쓴다. 문장부호가 얌전하면 노트가 아니다.

## 원본을 참고하되 베끼지 않는다

`references/template2-anatomy.md` 에 원본의 절 구성, 문장부호 실측, 소주제별 형태가
정리돼 있다. 새로 쓰기 전에 읽어라. 가져올 것은 순서와 비중과 온도이고, 문장과
소재는 가져오지 않는다. 소재만 MSA로 바꾸고 문장 구조를 그대로 복사하면 읽는 사람이
알아본다.

## 근거 없는 문장을 쓰지 않는다

이 보고서의 소재는 실제 코드다. `msa-evidence-mining` 스킬이 만든
`_workspace/01_evidence.md`에서 근거를 가져오고, 거기 없는 사실은 쓰지 않는다.

특히 조심할 것:
- 숫자(포트, 임계값, 행 수, 측정치)는 반드시 근거 파일에서 옮긴다. 지어내면 발표에서 깨진다.
- "~라고 한다" 수준으로 아는 개념은 아는 만큼만 쓴다. 교수님이 "깊게 파지 않아도
  된다, 필요한 이유는 알겠다면 충분하다"고 한 범위가 있다. 그 선을 넘겨 아는 척하는
  서술이 오히려 감점 요인이다.
- 파일 경로와 클래스명은 실제 저장소 것을 그대로 쓴다.

## 분량

A4 기준 6~9쪽. Lesson Learned가 전체의 55% 이상, 트러블슈팅이 20% 안팎.
설명(도입)이 길어지면 개론 요약처럼 읽히므로 1.5쪽을 넘기지 않는다.

## 후속 요청 처리

- "이 절만 다시" → 해당 절만 고치고 나머지 문장은 건드리지 않는다. 전체를 다시 쓰면
  사용자가 이미 확인한 부분까지 바뀐다.
- "분량 늘려줘" → 새 소주제를 추가하지 말고, 기존 소주제에 헤맨 과정을 덧붙인다.
  소주제 개수를 늘리면 각 절이 얕아진다.
- "더 사람같이" → 문단 길이 편차와 1인칭 회고 비중을 먼저 손본다. 어휘 교체는 그다음.
