# MSA 보고서 오케스트레이터

## 실행 모드

**하이브리드.** Phase마다 성격이 다르다.

| Phase | 모드 | 이유 |
|---|---|---|
| 1. 근거 수집 | 단독 | 조사는 한 사람이 일관된 기준으로 해야 출처가 섞이지 않는다 |
| 2. 그림 + 집필 | **에이전트 팀** | 그림과 본문이 서로를 참조한다. 그림 목록이 절 구성을 바꾸고, 절 구성이 그림 배치를 바꾼다 |
| 3. 검수 | 단독 | 검수자는 집필 과정을 모르는 편이 낫다. 팀 대화에 섞이면 이미 합의된 것을 지적하지 못한다 |
| 4. 조립 | 단독 | 기계적 작업 |

## Phase 0: 컨텍스트 확인

시작할 때 `_workspace/` 상태를 보고 실행 모드를 정한다.

| 상태 | 요청 | 실행 |
|---|---|---|
| `_workspace/` 없음 | 무엇이든 | **초기 실행** — Phase 1부터 |
| 있음 | "이 절만", "그림만", "docx만" | **부분 재실행** — 해당 Phase만 |
| 있음 | "더 사람같이", "분량 늘려" | Phase 2(집필)~4 |
| 있음 | 소재가 바뀜 (다른 프로젝트) | `_workspace_prev/`로 옮기고 **새 실행** |

부분 재실행일 때 앞 단계를 다시 돌리지 마라. 근거 수집은 몇 분이 걸리고, 결과가
바뀌지 않는데 다시 도는 것은 순수한 낭비다.

## Phase 1: 근거 수집 (단독)

**evidence-miner** 를 `model: "opus"`로 호출한다.

- 입력: 작업 디렉토리의 PDF·txt·`msa-lecture/`, 팀 저장소 URL
- 출력: `_workspace/01_evidence.md`
- 완료 조건: A~G 7개 절이 모두 채워지고, 모든 항목에 출처가 붙어 있음

집필을 이 단계와 겹치지 마라. 근거가 절반만 모인 상태에서 쓰기 시작하면
나머지 절반을 기억으로 채우게 된다.

## Phase 2: 그림 + 집필 (에이전트 팀)

팀: **sketch-artist** + **report-writer** (2명). 리더는 오케스트레이터.

```
TeamCreate(team_name="report-team", members=[sketch-artist, report-writer])
TaskCreate:
  T1 report-writer  : 절 구성과 필요한 그림 목록 확정 → sketch-artist 에게 전달
  T2 sketch-artist  : 그림 제작 + 자체 검수 (T1 의존)
  T3 report-writer  : 본문 집필 (T2와 병행. 그림 완성분부터 배치)
  T4 양쪽           : 배치 순서 합의 — 그림이 본문보다 먼저 온다
```

이 둘을 따로 돌리면 안 되는 이유: report-writer가 "여기 그림이 필요하다"를 발견하는
시점은 본문을 쓰는 중이고, sketch-artist가 "이 개념은 한 장에 안 들어간다"를 발견하는
시점은 그리는 중이다. 두 발견이 서로의 계획을 바꾼다. 순차로 돌리면 한쪽이 반드시
상대의 이미 끝난 결과에 맞춰 타협하게 된다.

- 출력: `_workspace/diagrams/*.{js,png}`, `_workspace/02_diagrams.md`,
  `_workspace/03_manuscript.md`
- 완료 조건: 원고의 모든 `![](...)`가 실제 파일을 가리키고, 모든 PNG가 원고에서 쓰임

## Phase 3: 검수 (단독)

**human-voice-qa** 를 `model: "opus"`로 호출한다. 출력 `_workspace/04_qa.md`.

검수자가 제일 먼저 도는 것은 하드 게이트다. 정의는
`template2-report-writing/scripts/voice-gate.sh` 한 곳에 있고, 집필자와 검수자가 같은
스크립트를 돌린다. 큰따옴표, 중간점, 이모지, 답 없이 끝나는 의문형, 의문형 제목, 그림 뒤
캡션, 글이 자기를 설명하는 문장, 이름 자리표시자, 인용 블록(0개), 인용 앞 도입
한 줄 문단, 예고형 도입 문장. 사용자가 직접 반려한 항목이라 문체 취향이 아니라 통과
조건이다.

게이트를 늘릴 때 에이전트 정의 파일에 grep 을 새로 적지 마라. 스크립트를 고치고
`.md` 에는 항목 이름만 적는다. 예전에 양쪽에 복제돼 있다가 한쪽만 고쳐진 적이 있다.

- CRITICAL 0건 → Phase 4
- CRITICAL 있음 → report-writer에게 지적 목록을 넘겨 수정 후 재검수. **최대 2회.**
  3회째에도 남으면 남은 항목을 사용자에게 그대로 보고하고 판단을 맡긴다.
  같은 항목을 무한히 돌리는 것이 가장 나쁜 결말이다.

## Phase 4: 조립 (단독)

**doc-builder** 를 `model: "opus"`로 호출한다.

- 출력: 작업 디렉토리 루트의 `.docx`
- 완료 조건: 이미지 개수 == PNG 파일 개수, 표·문단 수가 0이 아님

## 데이터 전달

파일 기반(산출물) + 태스크 기반(Phase 2 조율).

```
_workspace/
├── 01_evidence.md      근거 — 모든 사실의 단일 출처
├── 02_diagrams.md      그림 목록 · 캡션 · 배치
├── 03_manuscript.md    원고
├── 04_qa.md            검수 결과
└── diagrams/           NN_이름.js (재생성용) + NN_이름.png
```

`_workspace/`는 지우지 않는다. 부분 재실행과 사후 검증이 전부 여기에 의존한다.
특히 `.js` scene 파일 — 이게 없으면 그림 하나를 고치려고 처음부터 다시 그려야 한다.

## 에러 핸들링

| 상황 | 처리 |
|---|---|
| 저장소 클론 실패 | 1회 재시도 → readme만 WebFetch. 보고서에 "저장소 미확보" 명시 |
| Chrome이 매달림 | `--headless=old` 확인. `=new`는 이 환경에서 멈춘다 |
| 한글이 손글씨로 안 나옴 | 폰트 base64 임베딩 실패. 그림 전체를 다시 굽는다 |
| 근거끼리 상충 | 지우지 말고 둘 다 적는다. 불일치 자체가 트러블슈팅 소재다 |
| QA CRITICAL 반복 | 2회까지만 자동 수정. 이후 사용자에게 넘긴다 |
| 이미지 누락 | 조립은 완료하되 누락 목록을 **반드시** 보고 |

## 테스트 시나리오

**정상 흐름** — "팀 프로젝트 참고해서 템플릿2 양식으로 MSA 레포트 써줘"
→ Phase 1(근거 A~G) → Phase 2(그림 5장 + 원고 7쪽) → Phase 3(CRITICAL 0) →
Phase 4(docx, 이미지 5개 확인) → 사용자에게 파일 경로와 피드백 요청

**에러 흐름** — 저장소가 private이라 클론 실패
→ 1회 재시도 실패 → readme WebFetch도 404 → `_workspace/01_evidence.md`에
"팀 저장소 미확보"를 명시하고 강의 템플릿 코드(`msa-lecture/`)만으로 진행 →
원고에서 팀 커스터마이징 절을 뺀다 → 사용자에게 "저장소 접근이 안 돼 팀 변경사항
절이 빠졌다"고 먼저 보고

**부분 재실행 흐름** — "3번 그림만 다시, 화살표가 겹쳐"
→ Phase 0에서 부분 재실행 판정 → sketch-artist만 호출, seed 유지한 채 좌표 수정 →
Phase 4로 바로 점프 (Phase 1·2·3 건너뜀)

## 완료 후

사용자에게 피드백을 요청한다 — 결과물 품질, 팀 구성, 워크플로우 순서.
피드백이 오면 `references/` 없이 해당 대상을 직접 고치고 CLAUDE.md 변경 이력에 기록한다.

| 피드백 | 고칠 곳 |
|---|---|
| 특정 표현이 어색하다 | `voice-guide.md` 0절 금지표에 **지적받은 문장 그대로** + 고친 문장을 추가하고, 기계로 셀 수 있으면 `human-voice-qa.md` 축 0 grep에도 넣는다 |
| 글이 기계 같다 (범위가 넓음) | `template2-report-writing/references/voice-guide.md` |
| 그림이 깔끔하다 | `handdrawn-diagram/SKILL.md` 배치 원칙 |
| 사실이 틀렸다 | `msa-evidence-mining` 수집 순서 |
| 순서가 이상하다 | 이 파일의 Phase 구성 |

문체 지적을 받으면 일반화해서 적지 마라. `AI 같은 표현을 피한다` 는 다음 실행에서
아무것도 막지 못한다. 반려된 문장을 그대로 왼쪽에 박아 두는 것이 유일하게 작동하는
형태다. 셀 수 있는 것은 반드시 grep으로 내려서 검수자가 판단하지 않게 만든다.
