# report-template3 — 템플릿3 양식 준수 및 docx 생성

## 이 스킬이 하는 일

1. 템플릿3의 장·절 구조를 확인하고 어긋난 곳을 잡아낸다
2. 마크다운 소스를 **원본 템플릿과 같은 서식**의 docx로 변환한다

## 왜 서식을 직접 만들지 않고 원본에서 떠오는가

제출물은 같은 양식으로 걷혀서 나란히 비교된다. 글꼴·크기·정렬을 손으로 흉내 내면
미묘하게 어긋나고, 어긋난 티는 내용보다 먼저 보인다.
`scripts/build_docx.py`는 원본 docx의 문단 서식 조각(pPr/rPr)을 그대로 떠와서 새 본문에 입힌다.
그래서 손으로 맞출 서식 값이 없다.

## 구조 확인

장·절 목록, 절별 형식과 분량 기준은 `references/template3-structure.md`에 있다.
구조를 판단해야 할 때 그 파일을 읽는다. 여기에 옮겨 적지 않는 이유는 원본이 하나여야
어긋남을 잡을 수 있기 때문이다.

**바꾸면 안 되는 것:** 장 제목 3개, 각 장의 절 번호와 순서
**바꿔도 되는 것:** 보고서 제목, 절 안의 내용, 2장 2절의 기술 이름, 3장 사례 개수

## 소스 작성

`references/template3-structure.md`의 "소스 파일 포맷" 절을 따른다. 요약하면:

```
TITLE: 보고서 제목
AUTHOR: 3반 홍길동

# Chapter 1. 고객 중심 서비스 이해

## 1. 서비스 개요

본문 문단.

## 2. 고객에게 제공하는 가치

- 항목: 설명
```

`**굵게**`, 표, 인용문은 쓰지 않는다. 변환기가 처리하지 않아 별표가 그대로 찍힌다.

## docx 변환

```bash
python3 .claude/skills/report-template3/scripts/build_docx.py \
    <소스.md> <출력.docx> \
    [--template ~/Desktop/닥스/코드이해_개인과제_템플릿3.docx]
```

- 표준 라이브러리만 쓴다. `pip install` 필요 없다
- `--template`을 안 주면 `~/Desktop/닥스/코드이해_개인과제_템플릿3.docx`를 쓴다
- 원본 템플릿은 읽기만 한다. 덮어쓰지 않는다

## 변환 후 확인

변환이 성공해도 내용이 다 들어갔는지는 별도로 본다.

```bash
python3 - <<'PY'
import re, zipfile
x = zipfile.ZipFile("출력.docx").read("word/document.xml").decode()
for p in re.findall(r"<w:p\b.*?</w:p>", x, re.S):
    t = "".join(re.findall(r"<w:t[^>]*>(.*?)</w:t>", p, re.S))
    if t.strip(): print(t)
PY
```

찍힌 텍스트가 소스와 같은지, 장·절 제목이 다 있는지 눈으로 확인한다.
Word에서 열어봐야만 알 수 있는 것(줄바꿈 위치, 페이지 나눔)은 사용자에게 확인을 넘긴다.

## 자주 나는 문제

| 증상 | 원인 | 대응 |
|------|------|------|
| `템플릿에서 다음 서식을 찾지 못했습니다` | 원본 docx가 다른 파일로 바뀜 | `--template`으로 진짜 템플릿3 경로를 지정 |
| 불릿이 하나로 이어짐 | 목록 사이에 빈 줄이 없음 | 목록 사이에 빈 줄을 넣는다 |
| 별표가 그대로 보임 | `**굵게**`를 씀 | 마크다운 강조를 지운다 |
| 코드블록 들여쓰기가 사라짐 | 삼중 백틱 밖에 씀 | 백틱 블록 안에 넣는다 |
