## 절별 작성 규칙

| 절 | 형식 | 분량 기준 |
|----|------|----------|
| 1-1 서비스 개요 | 문단 (불릿 없음) | 3~5문장 |
| 1-2 고객에게 제공하는 가치 | 불릿, `제목: 설명` 형태 | 3~5개 |
| 1-3 주요 고객 적용 사례 | 불릿, `대상: 쓰임새` 형태 | 3개 |
| 1-4 고객이 느낄 수 있는 한계 | 불릿, `한계 → 결과` 형태 | 3개 |
| 1-5 구조 전환 제안 | 한 줄 도입 문단 + 불릿 | 도입 1문장 + 3~4개 |
| 2-1 REST API의 등장 배경 | 문단 | 2~4문장 |
| 2-2 기술 선택 이유 | 불릿, `이유: 설명` 형태 | 3~4개 |
| 2-3 시스템 구조와 요청 처리 흐름 | 코드블록(구조도) + 흐름 나열 | 구조도 1개 + 단계 4~6줄 |
| 3-N 트러블슈팅 사례 | 소제목 + 증상/원인/해결 3줄 | 사례당 2~4줄 |
| 3 요약 | `✅ 트러블 슈팅 요약` 소제목 + 불릿 | 3개 내외 |

원본 템플릿은 1장 5개 절, 2장 3개 절, 3장은 사례 6개 + 요약으로 구성되어 있다.
사례 수는 실제 겪은 만큼 쓰되, **요약 항목은 반드시 넣는다.**

## 소스 파일 포맷

`build_docx.py`에 넘길 마크다운 소스는 아래 문법만 쓴다.

```
TITLE: 보고서 제목
AUTHOR: 3반 홍길동

# Chapter 1. 고객 중심 서비스 이해

## 1. 서비스 개요

본문 문단은 그냥 한 줄로 쓴다. 빈 줄로 문단을 구분한다.

## 2. 고객에게 제공하는 가치

- 첫 번째 항목: 설명
- 두 번째 항목: 설명

## 3. 시스템 구조와 요청 처리 흐름

```
main.py
 ├── routers/
 └── database.py
```
```

- `#` = 장, `##` = 절, `-` = 불릿, ``` 삼중 백틱 ``` = 코드블록(공백 유지)
- `1. `, `2. `처럼 숫자로 시작하는 줄은 한 줄이 한 문단이 된다. 절차를 적을 때 빈 줄을 넣지 않아도 붙지 않는다
- 그 외에 빈 줄 없이 이어진 줄들은 한 문단으로 합쳐진다. 문단을 나누려면 빈 줄을 넣는다
- 마크다운 강조·인용·표(`**굵게**`, 백틱 코드, `>` 인용, `|` 표)는 쓰지 않는다. 변환 시 기호가 그대로 글자로 찍힌다
- 불릿 목록 사이에 빈 줄을 넣으면 별개 목록으로 처리된다
